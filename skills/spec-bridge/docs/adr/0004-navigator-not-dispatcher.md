# 桥是导航员与档案员，不是调度员

用户已有两套流程引擎（OpenSpec + Superpowers，matt-to-goal），桥再造代理调度层等于造第二个引擎——正是 ADR-0001 拒绝的复杂度回归。桥只做两件事：**导航**（告知当前拍点与下一步）与**归档**（规格资产沉淀）；不代理调用外部工具，外部工具栈照常自己跑。变更台账共享：单一 `.bridge.yaml` 模板 + 单一归档目录，顶层 `workflow_kind: openspec | matt | builtin` 字段区分流程线。

## Considered Options

- **调度员**（桥代理调用 openspec/matt CLI，结果写入本地台账）：被否——桥与工具栈深度耦合，谁拥有变更真相变得模糊。
- **两套独立台账**（openspec 路径和 matt 路径各自一套）：被否——规格资产散落两处，桥失去横向价值。
- **纯对齐层**（桥不感知流程，只扫描两边目录合并根基线）：被否——丢掉导航角色。

## Consequences

- `scripts/vendor/` 引擎保留为 Stack C 兜底，不是桥的本职。
- 桥的输出只有两种形态：stdout 提示 + 台账字段；不存在对外部工具的调用代码。
